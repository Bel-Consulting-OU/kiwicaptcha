# KiwiCaptcha widget system (edition 6)

The current widget system from `KiwiCaptcha_Visual_Identity.pdf` edition 6
(23 October 2026, "current widget system"). The approved website sets the
visual parent. The compact status surface and the factor task form share
primitives and tokens and keep deliberately different task density. The
canonical Spiral Lock and outlined wordmark masters are unchanged.

## Files and integration

| File | Role |
| --- | --- |
| `widget-system.css` | The shared stylesheet used by the home page, the playground and the system gallery. |
| `widget-states.json` / `widget-states.js` | The English state content and tone inventory. |
| `widget-copy-v5.json` / `widget-copy-v5.js` | Proposed concise baseline translations for ten locale packs. Native-language review is a release task before release. |
| `widget-primitives.js` | The exact mark, the status icons and escaping. |
| `widget-view.js` | The compact status renderer. Pure view model in, static markup out. |
| `factor-view.js` | The one pure factor renderer used by every static example and print specimen. |
| `factor-adapter-outline.ts` | A proposed adapter contract. Its names are not existing product APIs. |
| `build-specimens.mjs` | Generates the website's specimens from the two renderers. |
| `spec/render.test.mjs` | Renderer and copy-inventory tests (`node --test spec/`). |

Static examples, the system gallery and the print specimens are generated by
the same two pure renderers. Separate hand-drawn HTML copies are not
authoritative. The live interactive lab belongs to the design site; this
repository's website stays JavaScript-free, so its gallery is generated at
build time and the interactive contract lives in `factor-adapter-outline.ts`.

## Layout contract

The compact status surface prefers 352 px and fits smaller host containers.
Its inset is 20 px block and 24 px inline with a 12 px corner. The leading
mark is 32 px and static. The grid is 32 px mark, flexible copy and a 20 px
state icon with 14 px gutters. The title is 20/24 in the host family at
Medium 500. The explanation is 15/20 and sits 5 px below the title. The
attribution is 12/16 in a quiet footer with no divider. Recovery is a text
action with a 44 px target.

The factor form prefers 384 px at natural height with a 12 px corner. Its
insets are 24 px top, 28 px inline and 20 px bottom. The caption is 13/16
beside a 26 px static mark. Close is a 44 px target with a 16 px SVG cross.
The heading is 28/30 Medium 500 with a 16/22 explanation. The field is a
14/20 label, an 8 px gap and a 48 px input (16/24; the code face is 18/24).
The primary action is full width at 48 px with a 17/24 centered label.
Utilities are 44 px text targets with no competing outline.

Both surfaces use border-box sizing, min-inline-size 0 and scoped selectors.
Margin, line-height, border and focus are explicit. The flexible text column
wraps long words so translated text never clips. Host typography is
intentional: the component fetches no font and a host supplies its family
through `--kc-font-family`.

## Verification

```sh
node --test packages/kiwicaptcha-widget-system/spec/    # renderer + copy tests
tsc --noEmit --strict factor-adapter-outline.ts         # adapter outline typecheck
node tools/ci/website-layout-matrix.mjs                 # layout matrix in headless Chromium
node tools/ci/website-pixel-shots.mjs                   # render specimens at 3x
python3 tools/ci/website-pixel-verify.py --measure      # pixel compare with the design PDF
```

The layout matrix covers every status view across the ten locale packs,
four container widths and both text sizes in both type families, plus every
factor view at three widths across both themes and both text sizes. The
pixel verifier locates each specimen on the PDF's own pages, normalizes to
the specimen's container width, checks solid color probes and bounds the
raster difference to the antialiasing budget.

## Boundary

This delivery changes the website and the visual prototypes. It does not
port the product runtime renderer. Audit the runtime before porting and wire
capability-driven recovery, typed delivery and code errors, authoritative
retry windows, expiry, demand and operation binding, cancellation and
stale-response rejection through `factor-adapter-outline.ts`. The security
boundary is unchanged: no specimen performs delivery, proof computation,
token issuance or grant verification.
