# kiwicaptcha-solver

The native solver library and CLI for KiwiCaptcha: the supported
automation path at the browser's price. Solver secrecy was never part of
KiwiCaptcha's model (public solvers already exist for peer systems), and
unauthenticated well-behaved automation deserves a supported tool instead
of a scraped widget. This crate concedes nothing a browser does not
already concede, and it charges exactly what a browser is charged: the
same caps, the same challenge JSON, the same wire token.

## The documented JSON flow

```
1. POST {endpoint}/challenge       body {"scope":"login"[,"algorithm":"argon2id"]}
   <- the bare challenge object (nonce, challenge, salt, algorithm,
      mKib, t, p, targetBits, ttlSecs, minDurationMs, prefix, and the
      optional decoy_field / execution_program / rsw_modulus keys)
2. solve                           sha256 | argon2id hash search, or the
                                   rsw sequential squaring, inside the caps
3. POST {endpoint}/siteverify      body {"secret","response","remoteip"?}
   <- the provider-shaped {"success":bool,"error-codes":[...]} JSON
```

The challenge fetch is the widget's own route and grammar: an HTTP POST
carrying a JSON body, never a bare GET (the deployment's challenge
controller answers 405 to anything else). The verify body is the
provider-compatible document the symfony `/siteverify` route documents;
`secret` is the server-to-server key that resolves the expected scope
server-side, `response` is the wire token, and `remoteip` is required only
when the deployment binds challenges to the client IP.

## CLI

```
kiwicaptcha-solver challenge --endpoint http://host/api/kcaptcha/challenge --scope login
kiwicaptcha-solver solve --endpoint http://host/api/kcaptcha/challenge --scope login \
                         --secret <siteverify-secret> [--remoteip 203.0.113.7] \
                         [--header "Cookie: session=..."] [--algorithm argon2id]
```

- `challenge` prints the raw challenge JSON for scripting.
- `solve` fetches, solves, and (with `--secret`) verifies end to end;
  without `--secret` it prints the token for the caller to carry in the
  protected form POST, exactly like the widget does.
- The verify endpoint defaults to the challenge endpoint with `/challenge`
  replaced by `/siteverify`; override with `--verify-endpoint`.
- Progress goes to stderr (`at N`, `found counter=...`); the
  machine-readable result is one JSON object on stdout.
- Exit codes: 0 verified (or solved with no secret), 1 refused/rejected
  (the server's error codes print on stdout), 2 usage or transport error.

## Sharing decision (why this is not a fork)

The algorithms are shared with the other solvers, not forked:

| Piece | Source | Why |
| --- | --- | --- |
| Token encoder | `kiwicaptcha::SolutionToken::encode` | byte-identical to the widget by construction (same encoder) |
| Caps | the core crate's re-exported constants | protocol/limits.json parity, enforced by the repo's CI gate |
| rsw base + proof form | `kiwicaptcha::derive_base`, `kiwicaptcha::proof_hex` | the verifier's own derivation functions |
| Challenge wire keys | the PHP `Challenge::toArray` key set | the endpoint's actual emission |
| SHA-256 / Argon2id loops | this crate, against the shared preimage | the verifier's `derive_hash` is private and the wasm solver is wasm-bindgen-shaped |

The search loops implement the documented preimage contract
(`SHA-256(prefix || counter || salt)`, and
`Argon2id(prefix || counter, salt, m_kib, t, p)` with the counter in
decimal). Equivalence is proven the strong way: the test suites run the
workspace's real verifier end to end over tokens this crate produces,
cross-check the winning counters against `kiwicaptcha::solve_for_test`,
and pin the token wire bytes to the shared
`protocol/solution-token-v1` fixtures (generated by the PHP encoder) and
the rsw proof to the trapdoor expectation under the shared
`protocol/rsw-identity-v1` fixture modulus.

## The caps (the browser's price)

| Cap | Value |
| --- | --- |
| Hash search space | 20,000,000 (`solver_max_hashes`) |
| SHA-256 target bits | 20 (`sha_max_target_bits`) |
| Argon2id target bits | 10 (`argon2_max_target_bits`) |
| Argon2id memory | 65,536 KiB (`argon2_max_m_kib`) |
| rsw squarings T | 10,000..=300,000 (`rsw_t_min`/`rsw_t_max`) |

A difficulty beyond a ceiling, Argon2id parameters outside the issued
contract, rsw parameters outside the protocol bounds, and a caller-supplied
hash cap above the documented maximum are all refused before any work is
spent. A search that exhausts the cap reports it instead of looping
without bound. A challenge armed with an execution program is refused
with `execution-unsupported`: that dimension needs the browser's sandboxed
interpreter and is deliberately outside the native path.

## Library

```rust
use kiwicaptcha_solver::{Challenge, SolveOptions, solve, verify_endpoint_request};

let challenge = Challenge::from_json(&challenge_response_body)?;
let solution = solve(&challenge, &mut SolveOptions::default())?;
let token = solution.token(&challenge);              // the wire token
let body = verify_endpoint_request(&secret, &token, None); // the POST body
```

`SolveOptions` carries the hash cap, a progress callback and a
`CancellationToken`; the solve stops promptly when the token fires.

## Transport

The CLI's HTTP client is std-only: no TLS, so http:// endpoints work
directly and https:// endpoints are refused with the documented remedy
(pipe the endpoint through a local plaintext proxy or an HTTP CONNECT
tunnel). The workspace has no HTTP client dependency anywhere, and adding
one for two POSTs would be the crate's heaviest dependency by far. The
client understands both Content-Length and chunked response framing, and
caps response bodies at 1 MiB.

## Tests

- `tests/solve_verify.rs` — golden vectors (pinned counters, shared token
  fixtures, the rsw trapdoor cross-check), the end-to-end solve → token →
  core-verifier chain for all three algorithms, cap enforcement, bounded
  exhaustion, cancellation and progress.
- `tests/cli_flow.rs` — the CLI against a stub deployment on 127.0.0.1
  that mints real challenges through the workspace issuer and verifies
  through the workspace verifier.
- `tests/http_client.rs` — the transport: both framings, the https
  refusal, the injection guards.
