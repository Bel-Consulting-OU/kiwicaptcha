## Recovery follows the actual failure.

Retry may reacquire or rerun the demanded flow. Mixed worker, driver or glue identities need a coherent asset reload. Required worker and execution evidence remain required.

<div class="table-wrap">

| State | Meaning | Recovery |
| --- | --- | --- |
| pending | Deferred execution has never started. | No extra human control; application invokes execute. |
| idle | Manual reacquisition/reset state after a credential or flow existed. | Native retry when provided by the driver. |
| connecting | Acquiring a challenge. | Bounded flow recovery on failure. |
| solving | Selected computation in progress. | Driver governs completion/failure. |
| done | Browser solver completed and produced a response token. | Host continues to authoritative server verification; later expiry remains possible. |
| failed | Terminal flow failure after bounded recovery. | Retry may reacquire or rerun the demanded flow. |
| expired | Credential validity ended. | Clear token and bindings; preserve the host form; retry reacquires. |
| worker-unavailable | Required off-main-thread solver unavailable. | Retry can reacquire; no silent memory-hard downgrade. |
| execution-unavailable | Required armed execution interpreter failed. | Retry reruns the flow; required evidence remains required. |
| solver-mismatch | Worker/driver/glue protocol identities inconsistent. | Reload a coherent asset set; never accept mismatched output. |

</div>

## A direct, readable task.

{{ gallery_factor() }}

One text field handles the whole code, paste and leading zeroes. Close cancels; a real host must dismiss its surface and return focus to the invoker. An invalid code keeps the context for correction. Expiry clears the code and offers a new attempt. The server owns resend and retry eligibility; a local timer cannot unlock a restriction. Pending controls prevent duplicate submission; cancel must abort work and invalidate late responses.

## Typography can grow. The layout follows.

{{ gallery_matrix() }}

Factor checks cover each task view, three widths, two type families, both text sizes and both themes. Natural height, logical alignment and a flexible text column prevent ellipses and clipping. ## The application still decides.

PoW response, ownership grant, FactorVerified, AuthorizedStepUp and the protected action are separate boundaries. The host verifies kind, lifecycle, scope, demand binding and the authoritative disposition before allowing an operation. A transaction summary must come from safe server context. The final application decision remains outside the branded widget; the visual specimens perform no real delivery, proof computation, token issuance or grant verification.
